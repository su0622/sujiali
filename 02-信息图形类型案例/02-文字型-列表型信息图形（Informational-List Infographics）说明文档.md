# 文字型 / 列表型信息图形（Informational / List Infographics）说明文档

> 类型定位：以可扫描的文字条目、短段落、编号、清单或卡片为主要信息载体。其主要价值是筛选、解释、归纳和快速检索，而不必以统计图表为中心。

## 1. 核心数据逻辑
基本单元通常是“条目记录”，字段可包括标题、序号、类别、说明、标签、图标、来源和可选指标。列表可按重要性、步骤、类别、字母、时间或地理位置排序。排序依据必须可解释。

## 2. 统计图形与计算
默认不要求统计图形。可选用类别计数、比例条、迷你图或小型条形图补充数量信息；若没有数值字段，应明确标注“无统计图形 / 无统计计算”。编号只表示顺序时，不代表排名或权重。

## 3. 视觉编码
- 点 / 图标：条目识别、类别标记。
- 线：分隔条目、建立分组或步骤顺序。
- 面 / 卡片：形成条目容器和分区。
- 字体层级：标题、关键词、正文、注释形成扫描路径。
- 色彩：分组和重点提示，需保持色彩之外的文字标签。
- 编号：仅在存在明确顺序时使用，避免把装饰编号误读为优先级。

## 4. 信息架构
标题与一句话概览 → 分类 / 筛选说明 → 条目列表或卡片 → 每条目的解释、图示或数据 → 来源。条目模板应保持一致，便于横向扫描。

## 5. 视觉叙事
可采用“总览—逐项解释—归纳总结”或“问题—清单—行动建议”。列表不必强行制造起承转合；其叙事重点是清晰、完整和易检索。

## 6. 案例证据状态
目前仓库没有用户提供的文字型 / 列表型案例图，因此以上为待案例验证的工作定义，不作为案例归纳结论。收到案例后，补充实际条目粒度、排序逻辑、文字与图像比例、是否使用统计图形及阅读路径。

## 7. 制作与检查
检查条目是否同一粒度、是否互斥或存在重叠、排序规则是否明确、每条文字是否足够精炼、版式是否利于扫描、是否有出处与更新时间。
