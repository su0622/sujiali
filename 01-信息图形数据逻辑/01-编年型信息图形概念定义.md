# 编年型信息图形概念定义

> 文档性质：类型学工作定义（v0.1）。本仓库坚持“案例证据优先”：有案例支持的内容标为**案例观察**；尚无对应案例的部分标为**待案例验证的工作假设**。新增案例后需修订本文件，不把通用设计建议伪装成案例结论。

## A. 基本数据逻辑（本质）

### 核心定义
以时间为主导索引，将事件、状态或指标变化按时间顺序组织。

### 数据结构判定
- 基本实体 / 记录粒度：事件 / 时间区间 / 状态变化；每条记录至少有时间字段，常含事件、主体、描述、阶段、数值。
- 关键字段：日期时间、持续时长、事件类别、阶段、可选定量指标。
- 核心关系：时间点与事件一对多；事件可分阶段，区间可重叠，需明确先后、持续时间及时间粒度。
- 适合的数据类型：DATA编年型S
- 不属于本类型的情况：仅仅使用某种装饰形状，不能证明数据具有该组织逻辑。

## B. 统计图形与计算方式
常借用时间序列折线图、甘特图、事件带、里程碑图；可计算间隔、持续时长、变化率、累计值。若只呈现离散事件，则无须伪造连续统计曲线。

区分三层：①原始数据的统计口径；②统计汇总或计算；③最终图形的视觉映射。若案例没有统计计算，明确写“无统计计算”，不得为了填充章节而虚构公式。

## C. 视觉编码（点、线、面、体、符号、色彩）
时间轴为主线；点表示事件/里程碑，线表示时间连续性或阶段，面表示时期/区间，颜色区分阶段或类别，图标编码事件类型。等距与非等距时间必须视觉诚实。

## D. 数据 / 信息架构
标题与时间范围 → 主时间轴 → 阶段分组 → 事件节点及注释 → 结果/影响。

## E. 视觉叙事架构
时间起点建立背景 → 按时间推进 → 关键节点形成转折 → 展示结果或长期趋势。

## 案例证据与交叉链接
- 已分析案例：暂无专属编年型案例；等待用户提供时间轴图。
- 证据边界：哪些判断来自图面观察，哪些依赖原始数据或外部资料，必须分别注明。
- 后续案例：新增报告后在此补充相对链接，并归纳共性、反例与分类边界。

## 制作与校验原则
1. 先验证数据结构，再选择图形，不从视觉样式反推数据逻辑。
2. 直接标注单位、口径、时间范围、地理范围和来源。
3. 检查编码是否符合知觉规律，避免面积、体积和色彩造成夸大。
4. 检查阅读路径、标签遮挡、图例、色彩对比和非颜色信息冗余。
5. 将数据事实、设计解释和推测明确区分。
