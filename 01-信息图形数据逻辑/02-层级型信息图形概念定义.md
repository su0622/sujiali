# 层级型信息图形概念定义

> 文档性质：类型学工作定义（v0.1）。本仓库坚持“案例证据优先”：有案例支持的内容标为**案例观察**；尚无对应案例的部分标为**待案例验证的工作假设**。新增案例后需修订本文件，不把通用设计建议伪装成案例结论。

## A. 基本数据逻辑（本质）

### 核心定义
以包含、从属、等级或深度关系为主导，将对象组织成可追溯的上下位结构。

### 数据结构判定
- 基本实体 / 记录粒度：节点 / 类别 / 父节点ID / 子节点 / 层级深度；必要时增加权重、数量或标签。
- 关键字段：类别、父子关系、层级深度、可选权重/数量。
- 核心关系：树结构、森林结构或有向无环图；须区分严格树状从属与多重关联网络。
- 适合的数据类型：DATA层级型S
- 不属于本类型的情况：仅仅使用某种装饰形状，不能证明数据具有该组织逻辑。

## B. 统计图形与计算方式
可借用树图、组织结构图、旭日图、矩形树图；若节点大小代表权重，可计算占比、父节点内构成比。层级关系本身不等于数值大小。

区分三层：①原始数据的统计口径；②统计汇总或计算；③最终图形的视觉映射。若案例没有统计计算，明确写“无统计计算”，不得为了填充章节而虚构公式。

## C. 视觉编码（点、线、面、体、符号、色彩）
位置/缩进/连线表示父子关系；节点面积仅在有权重时表示量；颜色区分层级或类别，线宽不应暗示未定义的权重。

## D. 数据 / 信息架构
总类 / 根节点 → 一级分类 → 子类 → 叶节点；提供路径、图例和节点标签。

## E. 视觉叙事架构
从整体到局部或从根到叶展开；也可从一个具体节点回溯上位类别。

## 案例证据与交叉链接
- 已分析案例：暂无专属层级型案例；等待用户提供树状、组织结构或分类图。
- 证据边界：哪些判断来自图面观察，哪些依赖原始数据或外部资料，必须分别注明。
- 后续案例：新增报告后在此补充相对链接，并归纳共性、反例与分类边界。

## 制作与校验原则
1. 先验证数据结构，再选择图形，不从视觉样式反推数据逻辑。
2. 直接标注单位、口径、时间范围、地理范围和来源。
3. 检查编码是否符合知觉规律，避免面积、体积和色彩造成夸大。
4. 检查阅读路径、标签遮挡、图例、色彩对比和非颜色信息冗余。
5. 将数据事实、设计解释和推测明确区分。
